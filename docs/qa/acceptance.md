# LogiMate 评测与验收

状态为验收方案。阶段实测结果与证据在[交付索引](../delivery/README.md)更新。需求编号由 [PRD](../product/prd.md)维护。

## 数据与实验规则

| 数据集 | 使用边界 |
| --- | --- |
| 改进集 | 生成训练轨迹和已复核纠正，包含演示主线 `LM-1001`。基础层以当前技能生成候选 |
| 开发验证集 | 候选选择、旧新技能对照、活动版本回放、RAG 和偏好参数调优 |
| 冻结最终测试集 | 100 条物流案例、至少 60 条售后问答。最终评测读取测试输入和标签。改进、调参与候选选择流程只访问前两类数据 |

按场景模板族与实体分组拆分，保存固定种子、数据版本、内容哈希和分组清单。核查事件顺序、观测时间、权限、政策版本和跨集近重复。物流集覆盖正确诊断、边界正常、证据冲突、数据不足和工具降级。售后集覆盖有解释依据、多个相关片段、无适用条款和政策冲突。若查看最终结果后调参，另开冻结批次重新验证，并保留原结果。

## 指标与输出

| 实验 | 对照与评分 |
| --- | --- |
| 物流误判 | A 为初始规则，B 为固定技能生成的规则，C 为演化后技能生成的规则。B/C 使用相同起始规则、改进集、基础层模型和生成预算。A/B/C 对相同的 100 条冻结证据执行同一个规则解释器。可判定样本的错判、拒答、关键缺口遗漏或执行失败都算错误。待核实样本须正确标记并给出标注所需缺口。报告各组错误数除以样本总数、A→B 与 B→C 的百分点变化和相对变化，并记录元层额外调用成本 |
| 事实幻觉 | 对相同冻结证据与同一模型比较自由汇总和结构化校验汇总。至少一项关键事实缺证据或出现虚假引用，该样本计一次。报告占总样本比例以及占已作答样本比例，另记拒答数、系统失败数、任务准确率和作答覆盖率 |
| 售后检索 | 对同一索引版本与查询比较关键词、稠密和混合路径。对有相关切片的问题，取各自前五里命中相关切片数除以标注相关切片数，并按查询宏平均，得 Recall@5。无相关条款的问题单列，核查能否说明证据不足 |
| 售后问答 | 关键事实、政策引用和可回答性同时正确才计对。以正确案例数除以全部案例数；应拒答的案例按标准判断，系统失败计错。记录各类错误和可回答样本的作答覆盖率 |
| 检索与工具时延 | 从检索入口到选定结果统计 p50、p95，另记向量路径超时后的关键词回退比例和耗时。答案生成单独计时。记录 MCP 重试次数与任务可完成率 |

百分点变化为两百分率之差。相对改善以基线作分母，基线为零时填 `null`。覆盖率定义为可回答样本中的有效作答数除以可回答样本数。客户端超时、数据缺失或模型异常按同一口径记录，重跑整批需保留原结果。每份报告归档 `mode`、模型 ID 与参数、数据版本和哈希、代码版本、规则与技能版本、运行预算、配置哈希、逐案例输入 ID、预期与实际、证据和失败分类。

无密钥模式实走 MCP、数据库、检索与规则执行，用于产品链路和回归验证。GitHub 发布前，真实 DeepSeek 运行端到端问答、候选规则和候选技能生成；物流 B/C 用真实模型产物，A/B/C 各跑 100 条，售后问答和幻觉对照跑完整冻结样本。检索指标使用真实本地编码和索引。30% → 18%、幻觉率下降 40%–50%、召回率提升 30% 及问答准确率超 95% 以实验目标登记。报告和简历引用实际结果、样本及模式。

## 验收用例与需求映射

| 用例 | 测试操作与通过条件 | 需求 | 阶段 |
| --- | --- | --- | --- |
| AT-01 | 在新 Compose 项目中迁移并播种两次，核对主键、业务关系、版本和数据哈希。不同角色与租户只能通过服务端绑定建立身份。重复提交同键创建会话只产生一条记录 | LM-NFR-01、LM-NFR-04、LM-NFR-05 | 01 |
| AT-02 | 用 `LM-1001` 及退款、赔付问题，分别触发协调、订单、仓储、物流、售后。结论可定位证据；歧义输入请求澄清，越权查询失败 | LM-FR-01、LM-NFR-01、LM-NFR-02 | 02 |
| AT-03 | 用真实 MCP 服务注入第一尝试超时、持续不可用、无记录、越权和字段非法。分别核对一次重试、部分结果和直接终止；单次 1.5 秒和取证阶段 8 秒的配置可从轨迹验证 | LM-FR-02、LM-NFR-01、LM-NFR-03 | 02 |
| AT-04 | 用已复核 `LM-1001` 反馈发起基础层任务。候选记录原版本、反馈及证据；未复核反馈和非法字段被拒；回放写入独立报告 | LM-FR-03、LM-NFR-02 | 03 |
| AT-05 | 用同租户历史产生元候选；同起点执行旧、新技能，检查实际生成步骤或候选差异，保留两种产物及 `skill_ablation` 报告；新的迭代能加载已采纳技能 | LM-FR-04、LM-NFR-02 | 03 |
| AT-06 | 审核前发布、活动基线过期及跨租户均被拒；两个并发发布只提交一个。合法审批和激活写审计，回滚恢复旧组合，新运行使用现行版本 | LM-FR-05、LM-NFR-01、LM-NFR-02、LM-NFR-04 | 03 |
| AT-07 | 用精确术语与同义改写走两路检索，核对有效条款与出处。对语义支路注入超时，按 800 ms 预算返回 `keyword_only`；两路失败时明确不可用 | LM-FR-06、LM-NFR-02、LM-NFR-03 | 04 |
| AT-08 | 同会话跟问可继承实体；同用户另一会话能召回相关偏好；异用户和异租户看不到；撤回后即使索引尚未清理也不再使用。清缓存后的同一会话可重建窗口 | LM-FR-07、LM-NFR-01 | 04 |
| AT-09 | 取证完成一部分时重启应用，按原 ID 和版本恢复，完成步骤不重复。中断离线 worker 后，新租约继续剩余案例，完成记录不重复。带相同幂等键重复写入只观察到一个结果 | LM-FR-07、LM-NFR-04 | 04 |
| AT-10 | 在桌面和窄屏浏览器、以键盘和鼠标操作排查、纠正、审批、回滚、恢复及复测视图。检查加载、空、部分、失败和完成状态 | LM-FR-08、LM-NFR-05 | 05 |
| AT-11 | 运行三类 CLI 评测及真实 DeepSeek 端到端，核对三组物流各 100、售后至少 60、基线、结果及失败后的分母。复读逐案例报告可复算汇总 | LM-FR-09、LM-NFR-02 | 06 |
| AT-12 | 干净目录按 README 启动、运行用户主线和回放；核对实测报告、开源许可、论文引用、简历指标和待公开文件及历史 | LM-NFR-05 | 06 |

版本激活与 GitHub 公开有不同的证据要求。激活依据开发验证集相对当前活动版本的回放。GitHub 公开同时要求六阶段功能验收和冻结集评测完成。指标偏离目标时保存实际结果及失败分析。
