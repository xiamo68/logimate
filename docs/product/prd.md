# LogiMate 产品需求文档

版本 1.0 · 需求基线已确认 · 功能实现待开始

## 目标与用户

供应链运营人员通常要从订单、仓储、承运商和售后记录中拼出同一订单的经过。LogiMate 用自然语言接收问题，在同一个工作台给出可核对的结论、证据和下一步。已核实的纠正可以驱动规则更新。审核员能看到变更及回放，决定是否生效。

| 用户 | 主要任务 | 成功标准 |
| --- | --- | --- |
| 运营人员 | 查询订单、多轮排查、查看证据、提交纠正、运行回放 | 能识别结论依赖哪些记录，知道哪些信息待核实 |
| 审核员 | 复核纠正、对照回放、批准或驳回、发布和回滚 | 能定位失效案例，追溯谁在何时批准哪个版本 |
| 演示访客 | 在本机体验合成案例、观察改进过程、复跑评测 | 可在无模型密钥的环境体验产品链路，从报告辨认模型模式、数据集和实验口径 |

演示访客通过回环地址入口选择合成租户的运营或审核身份。业务系统只读。应用允许写会话、偏好、反馈、回放和版本。公开版的数据及业务场景全部合成，范围为单机本地运行与公开代码交付。

## 工作流与状态

1. **排查。** 用户提问或选择示例。协调 Agent 识别意图、做合规校验、安排取证。订单、仓储、物流和售后 Agent 返回结构化证据。页面显示结果、缺口、规则版本和节点轨迹。订单号有歧义时要求补充，来源失败时仍展示可确认的事实。
2. **改进。** 运营人员从排查结果提交纠正。审核员复核后，运营发起基础层或元层离线改进。回放显示实际变化的案例、候选差异、基线和是否达到发布门槛。审核员可以批准、驳回、发布或回滚。
3. **复测。** 用户浏览已归档评测，看到模型模式、数据版本、基线、样本量、结果和逐案例定位。通过 CLI 复跑对应实验。

主线案例 `LM-1001` 的订单页显示已发货。仓库记录有出库但无已确认交接，承运商有标签创建但无揽收扫描。初始规则误判成承运商异常。纠正标记为 `awaiting_handoff`，并附仓储和承运商证据。改进后的规则把交接证据纳入判断；示例用来演示反馈及回滚，归入改进数据，不用于最终评测。接口顺序见[联调示例](../api/README.md#lm-1001-联调示例)。

## 功能需求

| 编号 | 能力 | 可观察的验收结果 | 所属阶段 |
| --- | --- | --- | --- |
| LM-FR-01 | 五类 Agent 和结构化编排 | 单次异常排查经过意图、合规、策略、领域取证和汇总。订单、仓储、物流、售后 Agent 均可从正常入口触发。执行轨迹能查看节点和工具调用 | 02 |
| LM-FR-02 | MCP 只读业务取证与容错 | 真实 MCP 客户端与工具服务完成订单、仓储、物流、售后查询。暂时不可用时按预算有限重试，持续失败时提示缺失来源 | 02 |
| LM-FR-03 | 根据复核纠正更新规则 | 运营提交 `LM-1001` 的纠正。基础层读取已复核反馈和证据，生成校验过的不可变规则候选并回放 | 03 |
| LM-FR-04 | 根据历史回放改进生成技能 | 元层修改可配置的生成步骤或反例要求。旧、新技能从相同起点各运行一次，报告展示生成行为及其产物变化 | 03 |
| LM-FR-05 | 版本审核、激活与回滚 | 未达门槛、未审核、审核权限不足或基线过期时无法激活。合格候选激活可见；回滚恢复已发布版本并保留审计 | 03 |
| LM-FR-06 | 售后政策混合检索 | 中文政策按标题和条款分块，关键词与稠密路径实际运行并融合。回答引用有效政策版本，语义路径超时可回退 | 04 |
| LM-FR-07 | 分层会话记忆与偏好 | 多轮查询使用当前会话上下文。显式保存的偏好可在本人新会话按语义召回，撤回后不再使用。重启后可接续任务 | 04 |
| LM-FR-08 | 轻量演示网页 | 从排查、改进到复测可在网页操作，宽屏与窄屏均能查看证据和状态。键盘可完成核心操作 | 05 |
| LM-FR-09 | 可复现评测 | 从冻结样本运行物流三组、售后检索与问答、事实校验对照，生成带分母、版本信息和错误样例的报告 | 06 |

## 非功能需求

| 编号 | 约束 | 可观察的验收结果 | 所属阶段 |
| --- | --- | --- | --- |
| LM-NFR-01 | 授权和隔离 | 服务端绑定租户、角色与资源归属。另一租户无法读取会话、证据、反馈、版本或记忆。操作员不能审批自己的提交 | 01、02、03、04 |
| LM-NFR-02 | 可追溯 | 已确认事实与诊断关联可访问证据。每次回放、发布、回滚均能追溯运行、输入版本和操作者，最终评测可定位逐案例结果 | 02、03、04、06 |
| LM-NFR-03 | 可控响应 | MCP 默认单次超时 1.5 秒、最多重试一次，取证默认总预算 8 秒。检索总预算 800 ms，超时显示回退结果或明确不可用 | 02、04 |
| LM-NFR-04 | 恢复与一致性 | 相同幂等请求只有一个结果。中断后继续绑定旧版输入和规则，已完成步骤可复用。并发发布只有匹配活动基线的事务可提交 | 01、03、04 |
| LM-NFR-05 | 本地复现与公开交付 | 从干净目录初始化并复跑已归档案例。报告标注合成环境和模型模式。核对公开材料与历史后才发布 GitHub | 01、05、06 |

## 结果与发布

产品质量按[评测和验收文档](../qa/acceptance.md)判断。简历原有的 30% → 18%、40%–50%、30% 和 95% 是实验目标。发布材料记录实测值、基线、分母、覆盖率及失败案例。演示必须跑通发布与回滚，全量评测同时保留未达到目标的结果。各阶段状态在[交付索引](../delivery/README.md)维护。
